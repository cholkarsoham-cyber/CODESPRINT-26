The Problem

SaaS companies lose 1–3% of revenue to third-party billing platforms — yet the core engine is a well-defined, solvable state machine.

💸

Revenue Leakage

Stripe Billing, Chargebee, Zoho charge per-transaction fees that scale linearly with growth.

🔁

Failed Payments

Without smart dunning, a single card decline leads to involuntary churn — silently losing customers.

📊

Lack of Visibility

MRR, churn rate, and subscription health are scattered across third-party dashboards you don't control.

Our Solution

A self-hosted billing engine with a strict lifecycle state machine, automated dunning, and a real-time revenue dashboard.

🏗️

Plan Catalog & Signup

Monthly / yearly plans with trial periods. Customers subscribe from a public pricing page with mock payment tokens.

⚙️

Server-Enforced State Machine

trial → active → past_due → suspended → cancelled. The API rejects any illegal state transition.

🔔

Billing Engine & Dunning

Auto-generates invoices on cycle date. Failed payment triggers dunning email → retry in 3 days → 2nd failure suspends.

⏰

Time Machine

POST /time/skip advances simulated time. Demo an entire 30-day billing cycle in under 5 seconds.

System Architecture

Built on the QuikIT monorepo conventions — multi-tenant, org-scoped, audit-logged.

┌──────────────────────────────────────────────────────────────────────┐ │ Browser │ │ (marketing) → Public Pricing Page + Plan Catalog │ │ (dashboard) → MRR Dashboard + Time Machine + Event Log │ └──────────────────────────────┬───────────────────────────────────────┘ │ React Query / fetch ▼ ┌──────────────────────────────────────────────────────────────────────┐ │ Next.js API Routes (wrapped in withOrgAuth) │ │ POST /api/subscriptions → Create subscription (Zod validated) │ │ POST /api/time/skip → Time Machine + Billing Engine │ │ GET /api/dashboard → MRR, Churn, Invoices, Events │ └──────────────────────────────┬───────────────────────────────────────┘ │ Prisma + db.$transaction ▼ ┌──────────────────────────────────────────────────────────────────────┐ │ PostgreSQL (schema: app_billing) │ │ BillingPlan · BillingCustomer · Subscription · Invoice · Event │ │ All queries scoped by orgId (multi-tenant isolation) │ └──────────────────────────────────────────────────────────────────────┘

5 models, all org-scoped, with cascade deletes and composite indexes.

  • price (Float)
  • interval (month/year)

BillingCustomer

  • orgId ★

Subscription

  • nextBillingDate

  • orgId ★

Invoice

  • amount (Float)

BillingEvent

  • subscriptionId

★ Every query filters by orgId — strict multi-tenant data isolation.

Billing Engine & Dunning Flow

What happens when you click "Skip 31 Days"

// POST /api/time/skip — the core billing job for each subscription where nextBillingDate ≤ simulated_now: 1. Create Invoice { amount: plan.price, date: billingDate } 2. Attempt payment via mockGateway(customer.paymentToken) // "tok_success" → paid | "tok_fail" → failed 3. if payment === "paid": → status = "active" → advance nextBillingDate by +1 month → reset retryCount to 0 → log event: "payment_succeeded" 4. if payment === "failed" AND retryCount === 0: → status = "past_due" → schedule retry in 3 days → send dunning email → log event: "payment_failed_dunning" 5. if payment === "failed" AND retryCount >= 1: → status = "suspended" → send suspension email → log event: "subscription_suspended" All wrapped in db.$transaction + writeAuditLog

Key Differentiators

What sets this apart from a basic CRUD billing form.

🔒 Multi-Tenant Isolation

Every Prisma query is scoped by orgId. No org can ever see another org's billing data. Enforced at the API layer, not just the UI.

🧮 Transactional Integrity

Invoice creation + payment attempt + status update + event log all happen inside a single db.$transaction. Partial failures roll back cleanly.

⏰ Time Machine

A single API call fast-forwards the engine's clock. No cron jobs, no waiting. The entire 30-day billing cycle runs in under 2 seconds.

📜 Complete Event Sourcing

Every lifecycle change is recorded in the BillingEvent table with a timestamp, type, and JSON details. The event log tells the full story.
